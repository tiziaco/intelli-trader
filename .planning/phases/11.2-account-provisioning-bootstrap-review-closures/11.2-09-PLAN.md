<objective>
Cut the four-node LIVE construction cycle by extracting the exchange registry (D-43), give
`PortfolioFactory` a REAL account authority at construction, wire the factory in as the sole
leaf-builder, split `add_portfolio`'s durable write from its runtime build, stop rehydrate from
re-entering creation, delete the two guards that existed only to make that re-entry safe, and
correct the flagship multi-portfolio fixture that becomes illegal the moment ACCT-03 lands.

Purpose: the original 11.2-09 asserted `materialize -> VenueAccountManager.account_for` with an
ACCT-03 raise, but no task could wire the VAM into `PortfolioFactory` — the LIVE arm has a
use-time cycle `portfolio_handler -> factory -> VAM -> execution_handler -> portfolio_handler`,
and the only way to break it with eager injection was a forbidden late-init / `Optional`
collaborator. D-43 dissolves the cycle by cutting its ONE false edge: `VAM -> execution_handler`
is a single Law-of-Demeter reach-in (`bring_online` writing `execution_handler.exchanges[pair]`),
so extract that `(venue, account_id) -> exchange` map into a composition-root-owned component both
handlers receive. With the cycle gone the factory holds a real VAM built before `compose_engine`,
`materialize` reaches `account_for` on live (venue-truth leaf, raises on missing/disabled), the
create/materialize split lands, the absence gate and the null-account early return are deleted,
**ACCT-07 closes STRUCTURALLY** and **ACCT-05 is trivially true**.

Output: a root-owned exchange registry shared by `ExecutionHandler` and `VenueAccountManager`; a
`PortfolioFactory` holding a real, mode-agnostic authority; `create` / `materialize` as separate
verbs composed by an unchanged `add_portfolio`; a rehydrate that only materializes; a
`_persist_definition` with no null-account escape hatch; and a fixture that names two real accounts.
