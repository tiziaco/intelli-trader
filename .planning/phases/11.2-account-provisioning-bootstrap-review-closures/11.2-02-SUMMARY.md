# Phase 11.2 Plan 02: is_deleted + Partial Unique Index Summary

Split D-32's portfolio lifecycle into two flags — `enabled` = PAUSED (keeps its venue
account), `is_deleted` = RETIRED (releases the `(venue_name, account_id)` pair) — and swapped
the plain `UNIQUE(venue_name, account_id)` constraint for a partial unique index
`WHERE NOT is_deleted`, declared identically in the SQLAlchemy registrar and in a new
single-head Alembic revision.

## Task 1 — the spike (RESEARCH Assumption A6 → evidence)

Partial-index kwargs had **zero in-tree precedent** (MED risk). The spike proved
`Index(..., unique=True, postgresql_where=~c.is_deleted, sqlite_where=~c.is_deleted)` emits a
genuine partial predicate on both engines:

```
SQLITE  : CREATE UNIQUE INDEX ... (venue_name, account_id) WHERE is_deleted = 0
POSTGRES: CREATE UNIQUE INDEX ... (venue_name, account_id) WHERE NOT is_deleted
```

SQLite renders `is_deleted = 0` because its Boolean has INTEGER affinity — semantically
identical. The predicate is a **column expression, not a string**, so one object serves both
dialect kwargs and they cannot drift.

The three kept assertions are mutually non-vacuous: an ignored `sqlite_where` degrades the
index to PLAIN and fails (a); a dropped index fails (b) and (c).

## Task 3 — registrar

- `Column("is_deleted", Boolean, nullable=False)`, **no `server_default`** (the migration's
  backfill default is dropped in the same batch, so both sides agree).
- Plain `UniqueConstraint` removed; `Index("uq_portfolios_live_account", ...)` declared
  **after** the `Table` so the predicate names a real bound `Column`. An index built from a
  table's own columns auto-attaches, so `create_all` still emits it.
- `read_all()` filtered to live rows, ORDERING CONTRACT preserved verbatim; `get()`
  deliberately left unfiltered (id-addressed — a caller holding the handle must see RETIRED,
  not `None`).
- `_select_columns` / `_row_to_dict` expose `is_deleted`, bool-coerced.
- Docstrings revised with the D-32 reasoning: **simultaneous** sharing is still DB-refused
  (both live rows are indexed; a *paused* portfolio is still live for this purpose), only
  **sequential** reuse becomes possible, and the "binds out-of-band writers" half survives
  because uniqueness stayed a database constraint — nothing moved to an application check.

## Task 4 — migration

`upgrade()`: `add_column(is_deleted, server_default=sa.false())` → batch: drop the default,
`drop_constraint(op.f("uq_portfolios_venue_name"), type_="unique")` (created NAMED by the p11
revision even though the registrar declared it unnamed), `create_index` with both predicates.
`downgrade()`: exact inverse in reverse order. No backfill beyond the `server_default`.

**Verified beyond the column-name parity gate:**

- Registrar and migration emit **byte-identical index DDL**.
- `uq_portfolios_venue_name` is gone from the migrated table; no `DEFAULT` survives on `is_deleted`.
- On the *migrated* schema: retired + live coexist; two live rows raise `IntegrityError`.
- Clean downgrade is an exact inverse (column dropped, plain constraint restored, index gone,
  stamped back at `p11_b2_uuid_fk_config_move`) and re-upgrade is replay-safe.
- A downgrade against a DB that **has** already reused an account fails loudly on the
  duplicate pair — the one-way property working as documented, not a defect.
