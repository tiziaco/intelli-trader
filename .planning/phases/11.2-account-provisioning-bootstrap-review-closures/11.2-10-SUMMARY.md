## Decisions Made
- **Guard signature preserved (`str | None`, no raise).** The plan behavior for the guard says "arms against the id it is given, with no substitution" and does not mention raising; the guard's T-11-19 contract is observe-only / never-halt. Tightening to `str` would have cascaded a mypy break into `VenueLifecycle._account_id` (`str | None`) and 9 test construction sites. Chosen: keep `str | None`, remove the substitution, relax the 3 internal helper signatures. The `store` is `Any`-typed, so this is fully mypy-clean.
- **AST gate over grep gate.** See Deviations — the grep acceptance criterion was unsatisfiable; AST cleanly excludes docstrings/comments and pins KEPT uses by `ast.Name` count.

**1. [Rule 1 - Plan factual drift] "Eight/five coercions" overcounts — only FOUR real live-path deletions.**

- **Issue:** The plan's objective/ledger claims eight (later "five surviving") live-path coercions. Tree-wide there were 5 code coercions of `or DEFAULT_ACCOUNT_ID`; only 4 are on the live venue path (assemble `:130`, okx_plugin `:358`/`:473`, venue_uid_guard `:165`). - **Fix:** Executed the four real deletions; recorded sites 1-4 and 6 as ABSENT.
- **Verification:** `grep 'or DEFAULT_ACCOUNT_ID' itrader/venues/` before = 4 code + 2 docstring; after = 0 code + 2 docstring.

**2. [Rule 1 - Plan factual drift] Load-bearing coercion NOT swept.**
- **Issue:** The 5th tree-wide coercion, `admission_manager.py:150`, is mandatory (backtest portfolios have `account_id=None`).
- **Fix:** Left it intact; it is outside `itrader/venues/` and outside the gate's negative scan.

**3. [Rule 3 - Unsatisfiable acceptance criterion] `grep -c 'or DEFAULT_ACCOUNT_ID' itrader/venues/ == 0` is impossible.**
- **Issue:** `bundles.py:83` and `:113` contain the literal `spec.account_id or DEFAULT_ACCOUNT_ID` inside DOCSTRINGS, and `bundles.py` is deliberately kept (governing rule). A raw `grep -c` returns 2 forever.
- **Fix:** Built the gate as an AST `BoolOp(Or)` scan that only counts real code coercions; docstring/comment mentions cannot trip it. Recorded before/after counts above.

**4. [Rule 1 - Plan factual drift] `compose.py` has no code coercion — excluded from the positive half.**
- **Issue:** The plan's positive-half file list includes `compose.py`, but it holds 0 code-level `DEFAULT_ACCOUNT_ID` (2 docstring refs only, plan 03 removed the code). Asserting "present" there would fail.
- **Fix:** Excluded `compose.py` from the positive half; documented it as a KEPT docstring-only file. Matches the plan's own flagged planning assumption.

**5. [Rule 3 - False-green acceptance] `subprocess` grep and the gate docstring.**
- **Issue:** The acceptance `grep -c 'subprocess' <testfile> == 0` would have tripped on the word appearing in the gate's own prose docstring.
- **Fix:** Reworded the docstring to avoid the token entirely (the gate genuinely imports no subprocess module); `grep -c` now returns 0.

**6. [Doc drift — flagged, not fixed] `bundles.py` docstring example is now stale.**
- **Issue:** `bundles.py`'s `get` / `account_for` docstrings say "callers apply `spec.account_id or DEFAULT_ACCOUNT_ID` before calling." After this plan the callers RAISE on a missing id instead of coercing.
- **Decision:** `bundles.py` is NOT in `files_modified` and the code-wins brief forbids editing it to satisfy a grep. Its NORMATIVE rule ("account_id is REQUIRED and UNCOERCED; normalizing in two places is how the registry and memo disagree") still holds and is MORE strongly honored now (zero live-path normalization). Only the parenthetical example of HOW callers produce the key is stale. Left untouched; flagged here for a possible follow-up doc fix.
