# Phase 11.2 Plan 03: Venue-Aware Fee-Model Provider Summary

`fee_model_provider` now takes the order's own `(venue, account_id)` pair and resolves
`execution_handler.exchanges` inside the call, replacing a zero-arg closure that captured the
paper compute exchange at wiring time — and the live root's comment that made that
venue-blindness look like a venue-aware provider finding nothing has been replaced with the truth.

## The None-Handling Contract (audit item 2 — recorded as required)

The audit flagged that a silent miss on account resolution would reproduce the very defect this
plan closes while the oracle and suite stayed green. The chosen contract:

| Situation | Resolution | Loud? |
|---|---|---|
| No portfolio read model | `DEFAULT_ACCOUNT_ID` | no — one account exists by construction |
| `account_for` returns `None` | `DEFAULT_ACCOUNT_ID` | no — this is EVERY backtest portfolio |
| Pair resolves no exchange, or exchange has no fee model | `Decimal("0")` | **YES** — `logger.warning` naming the exact pair |
| No provider wired at all | `Decimal("0")` | no — construction-time absence, test-only |

**Why the coercion is not the silent fall-through the audit feared.** `Portfolio.account_id` is
`Optional[str]` and `backtest_trading_system.py:578-583` passes no `account_id`, so **every golden
portfolio reaches this lookup with `None`**. Raising or refusing there would break the oracle on
the first BUY. Nor can `portfolio_handler is None` serve as a live/backtest discriminator: unlike
`ExecutionHandler` (which is deliberately given no read model in backtest), `AdmissionManager`
receives the read model on **both** arms. So the coercion is mandatory and is exactly the
convention already used at `venues/okx_plugin.py:303`, `venues/assemble.py:133` and
`backtest_trading_system.py:571`.

What must never be silent is the **outcome**, and that is where the loudness went: a pair that
resolves no fee model books zero commission headroom, and now says so with the pair that missed.
This is oracle-dark (the golden pair resolves the paper `ZeroFeeModel`, so the branch never fires
during the golden run) and is proven by `test_unregistered_pair_degrades_to_zero_without_raising`.

`ExecutionHandler._resolve_account_id`'s explicit prohibition on `or DEFAULT_ACCOUNT_ID` is
preserved and the asymmetry is documented at both sites: there the pair picks an **authenticated
session** (coercion = MPORT-07, submitting through another account's credentials); here it picks a
**fee model for a pre-trade estimate** and nothing is submitted.

## Deviations from Plan

### Rule 3 — blocking issue: pytest was testing the WRONG TREE

The editable install resolves `itrader` to the **main checkout**, not this worktree. The first
post-edit test run reported a stale traceback (`self.fee_model_provider()` at `:142`) against code
that no longer existed on disk. Every test command in this plan was therefore run as
`poetry run env PYTHONPATH=<worktree-root> pytest …`. A plain `poetry run pytest` in a worktree is
a **false-green** — it can report a suite green against code you did not change.
*Baseline note:* the pre-change baselines (2879/6, oracle green, mypy 260) were taken via the
shadowed path, but the main checkout sits on the identical commit `1cad5095` with a clean tree, so
those numbers are valid for the pre-change tree.

### Blast radius: the plan named 1 test file; 5 needed changing, plus 1 production file

### `admission_exchange` deleted; `DEFAULT_ACCOUNT_ID` use relocated

must_have truth #4 pins `compose.py:259` as a "deliberately KEPT `DEFAULT_ACCOUNT_ID` site". After
the change the provider was its only consumer, so the plan's own action text authorized deleting
it, and the now-unused `DEFAULT_ACCOUNT_ID` import at `compose.py:54` went with it (verified: no
module imports it from `compose`). **The behavioural truth is preserved** — the backtest arm still
resolves `('paper', DEFAULT_ACCOUNT_ID)`, now from `AdmissionManager._resolve_account_id`. The
constant was **relocated, not coerced away**, so ACCT-04's intent survives at a new address.
Downstream ACCT-04 work should look for it in `admission_manager.py`, not `compose.py`.

### Named Protocol widened instead of an inline `Callable`

The plan asked for `Callable[[str, str], "Optional[FeeModel]"]` at the pass-through sites. The
codebase already has the named `FeeModelProvider` Protocol as the seam type; widening it is
equivalent, narrower, and keeps the `runtime_checkable` conformance tests meaningful. The inline
`Callable` would have left the Protocol declaring a stale zero-arg contract.
