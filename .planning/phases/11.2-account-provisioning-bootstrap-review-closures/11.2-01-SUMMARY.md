# Phase 11.2 Plan 01: Required state_storage on the Simulated Account Seam — Summary

Made `state_storage` a required keyword on both simulated account leaves **and** on the
paper `account_factory` closure — the seam `PortfolioHandler._new_compute_account`
actually calls — deleting the `PortfolioStateStorageFactory.create("backtest")` fallback
and the `getattr(config, ..., default)` reads that silently substituted a private
backend and a float zero for missing wiring.

## What Was Built

**Task 1 — the leaves refuse construction without their seam** (`297a6db1`, RED at `af45ee2f`)

`SimulatedCashAccount.__init__` and `SimulatedMarginAccount.__init__` now declare
`state_storage: "PortfolioStateStorage"` — keyword-only, no default. The fallback body
that minted a private in-memory backend is deleted, along with the now-unused
`PortfolioStateStorageFactory` import in that module.

The defect this closes (11.1-REVIEW **WR-04**) is not tidiness: a leaf on a private
backend routes reserved cash, locked margin and its cash-operation audit trail to an
object nobody else holds, so the live restart path
(`state_storage.rehydrate(account)`) repopulates the *portfolio's* instance and the
account silently loses every reservation. Backtest reads those containers nowhere else,
so the byte-exact oracle and the whole suite stay green while it happens.

**Task 2 — the seam that is actually called loses its defaults** (`eb01898a`, RED at `3712cfbb`)

- the `account_factory` closure inside `PaperVenuePlugin.build_bundle`: all four
  parameters (`initial_cash`, `enable_margin`, `account_id`, `state_storage`) are
  keyword-only with no defaults;
- `PaperVenuePlugin.new_account`: plain attribute reads replace every
  `getattr(config, ..., default)`; cash enters the Decimal domain at the boundary via
  `to_money(config.initial_cash)`;
- `new_account` raises `ConfigurationError` when the config names no seam.

Narrowing only the constructors would have closed the trap one layer *below* where
portfolios are built — the closure's own `= None` would keep supplying the argument the
constructor demands.

**Task 3 — signature-level pin + full gate** (`a09919e1`)

`inspect.signature` assertions on both leaves, because the behavioural `TypeError` tests
would still pass under a re-defaulted `state_storage=None` paired with an explicit
`raise` — precisely the Optional-collaborator shape this phase removes.

## Deviations from Plan

### Corrections to false or stale plan claims (code wins)

**1. [Rule 1 — false plan truth] The "AttributeError on a missing knob" behaviour is NOT achievable as written, and `bundle.py` was deliberately left alone.**

Task 2's `<behavior>` claimed "a config missing one raises `AttributeError`, not a
silent `0.0`/`False`/`None`". It cannot: the config type is `VenueAccountConfig`
(`itrader/venues/bundle.py:102-110`), which itself declares `initial_cash: Any = 0.0`,
`enable_margin: bool = False`, `state_storage: Any = None`. A plain attribute read still
yields those defaults.

Considered and **rejected**: making those three fields non-defaulted. It requires
`kw_only=True` on the frozen dataclass (they sit after six already-defaulted fields) and,
decisively, it forces `OkxVenuePlugin.build_bundle:311` — which legitimately supplies
none of the three, because venue-cached truth takes no wiring-supplied cash or seam — to
pass placeholder values at build time, reintroducing a `0.0` float literal on the venue
path. That is a worse shape than the one being deleted.

What was done instead, and what is therefore **actually true**:
- no production path can produce such a config — `account_factory` requires all four
  explicitly, and it is the only route to `new_account` in production;
- `new_account` raises `ConfigurationError` (not `AttributeError`) if a `None` seam
  reaches it anyway, which is the *backstop* must-have truth #6 asks for and matches the
  `PortfolioStateStorageFactory` refusal convention the plan cites.

The literal `AttributeError` wording is recorded as **not achieved**; the fail-loud
property it was reaching for **is**.

**2. [Rule 1 — false plan truth] "no float literal reaches a money field / the `0.0` float default is gone" holds only inside `paper_plugin.py`.**

Survivors outside this plan's file set, unchanged and out of scope:
`itrader/venues/bundle.py:108` (`initial_cash: Any = 0.0`) and
`itrader/portfolio_handler/account/simulated.py:112` / `:693`
(`initial_cash: float | Decimal = 0.0`). The acceptance greps were scoped to
`paper_plugin.py` accordingly. Note the `to_money` addition is **value-inert**:
`Account.quantize_cash` already routes through `to_money`, so this is a boundary
discipline, not a behaviour change — which is why the new Decimal test asserts on the
value the *constructor receives*, not on `account.balance` (that would have been a
false-green gate).

**3. [Rule 1 — wrong file list] `files_modified` named the wrong test files.**

Neither `test_account_conformance.py` nor `test_account_ownership.py` constructed a bare
account (the latter's only hit was a docstring mention). The real bare-construction sites
were `tests/unit/portfolio/test_cash_manager.py:39,50`,
`tests/unit/portfolio/test_portfolio_handler.py:746,770,782` and
`tests/unit/portfolio/test_wr04_lock_fits_buying_power.py:70`. All three files were added
to scope. `test_account_conformance.py` needed no change.

**4. [Rule 1 — stale anchors] Line numbers drifted; symbols were located instead.**

`build_bundle` is at `paper_plugin.py:150` with the closure at `:172-194` (plan said
`~:73-117`); `new_account` is at `:101` with the `getattr` reads at `:142-144` (plan said
`~:136-150`). The parameter literals the plan quoted were exact. The plan's instruction to
"introduce `*,` before `state_storage` if not present" was moot — the marker already

**5. [Rule 1 — stale count] `mypy` reports 260 source files, not the plan's 282.**

Pre-change and post-change both read 260. The plan's number is stale; the gate was

### Auto-fixed blocking issues

**6. [Rule 3 — blocking] `tests/support/venue_wiring.py` was not in scope but had to change.**

`compute_account(...)` is the single shared recipe behind ~46 call sites across 20 test
files, and it documented "`state_storage` is normally omitted: the leaf then builds a
private in-memory backend" — i.e. it *depended on the deleted fallback*. Removing the
fallback without touching it would have broken those sites wholesale. A new
`in_memory_state_storage()` helper was added and `compute_account` now mints one when the
caller supplies none.

This is the right home for the convenience: tests genuinely have no portfolio seam to
share, so the in-memory choice becomes a test's own explicit statement rather than a
production constructor's silent assumption.

**7. [Rule 3 — blocking] The one-line `paper_plugin` caller fix landed in Task 1's commit.**

Narrowing the constructors leaves their single production caller type-incorrect
(`Any | None` into a non-Optional parameter). To keep each commit green, the minimal
`config.state_storage` read moved into Task 1; Task 2 then added the closure narrowing,
`to_money`, the refusal and the docstrings.

### Environment note (not a code deviation)

`pytest` and `mypy` must be run as `PYTHONPATH=. poetry run …` inside a worktree — the
in-project `.venv` editable install resolves `itrader` to the **main checkout**, so the
first GREEN check reported a false failure against unmodified code. Every gate above was
re-run with `PYTHONPATH=.`. `make test` was not used (it exports
`ITRADER_DISABLE_LOGS=true` and aborts in worktrees on a missing `.env`).
