# Phase 11.2 Plan 07: Store-Derived Live Boot + D-36 Feed Binding Summary

The live boot now reads `for row in manager.read_enabled_for(venue): manager.bring_online(row)`,
runs assembly above rehydrate, computes no account identity of its own, and binds the ONE feed
to a venue *connection* (not a "primary account") through a new `FeedConnectionBinder`.
`live_trading_system.py` shrank ~483 net lines; the six spec-derived boot helpers, the
primary-account concept, and `feed.set_provider` are gone from that file.

## What was built

**Task 1 (commit `53ae84ef`) — hand the boot to VenueAccountManager.**
Replaced the six helpers (`_account_ids_for_spec`, `_mint_account_rows`,
`_build_account_specs`, `_attach_venue_accounts`, `_venue_of`, `_read_account_secret_ref`)
with the manager bring-up loop (ACCT-01/ACCT-02). Reordered the boot to distinct-account
check → venue assembly → rehydrate (D-20). `assert_distinct_accounts` now reads persisted
rows only. `venue_accounts` stays `{}` — the per-portfolio account attach is plan 08's job.
Net −483 lines; no new `def`/`class` added (D-35 grep clean).

**Task 2 (commit `92af2772`) — D-36, delete "primary account".**
New `FeedConnectionBinder` owns the ONE feed's borrowed data connection: it binds the first
available streaming connection, re-borrows when that account is retired/disabled, and
unbinds+warns when none is left. `VenueAccountManager` drives it from `bring_online` /
`rebind_feed`. Deleted `_primary_lifecycle`, the dead `assemble_venues` plural form,
`primary_provider`, the `index == 0` ordering contract, and `feed.set_provider` from the
live root. Session warmup/subscribe + halt-signal wiring read the bound provider through the
binder. TDD behaviour tests cover the four D-36 rules.

**Task 3 (commit `6269c721`) — rewrite the blast radius + static gate.**
Rewrote the affected tests against the new public seams (D-37): spec-derived derivation
tests deleted as meaningless (covered by the manager unit tests); okx-boot tests provision a
durable `venue_accounts` row on a Postgres spine and read the single lifecycle / binder
provider. Added a `tokenize`-based static gate that fails if any of the six deleted helpers
returns as live code (catches the credential-skipped e2e file + the mypy `ignore_errors`
blindspot). Import sweep dropped the now-dead `Iterable`.

## Deviations from Plan

### Owner descope (pre-authorised)
**SystemSpec.portfolios NOT deleted.** The owner ruled the field must stay (read by the
backtest path `backtest_trading_system.py:564` and ~50 e2e `scenario.py` files). It became
unused on the live path (the live readers went with the deleted helpers). `system_spec.py`
therefore dropped out of `files_modified`. Its full removal is a later-phase concern once the
backtest path is also store-derived.

### CODE-WINS corrections (audited discrepancies)
- Plan/CONTEXT said `system_spec.py` is 4-space — it is **TABS**. Moot (not edited).
- Task 1's `grep -c ...six... itrader/` = 0 is unachievable: 5 files (`portfolio_handler.py`,
  `conformance.py`, `reconciliation_coordinator.py`, `assemble.py`, `portfolio.py`) plus
  `tests/unit/venues/test_okx_plugin.py` still carry the names in **comments/docstrings only**.
  **Resolution:** the static gate (Task 3d) scopes to CODE identifiers (tokenize skips comments
  and strings), so historical prose is tolerated while a real reference fails. The stale
  comment refs were left in place (out of this plan's file scope; touching them risks colliding
  with sibling plans).
- Task 1's `grep -cE '^\+\s*(def |class )'` = 0 is satisfied by the pure-deletion diff; the
  added bring-up loop + manager/binder construction are wiring inside the existing
  `build_live_system` body (no new def/class/branch) — verified by reading.
- Suite floor 2879 is stale; real baseline was 2974. After deleting the now-meaningless
  spec-derived tests and adding the binder + gate tests, the count is **2954** (still well
  over the floor).

### Task 1/2 boundary + feed handling (internal-contradiction resolution)
The plan's Task 1 both said "nothing else from the old assembly block is needed" and "do not
touch the feed binding" — contradictory, because the provider construction referenced the
deleted `account_specs`. **Resolution:** Task 1 deleted the provider construction +
`feed.set_provider` (it could not compile otherwise) and left the feed *unbound*; Task 2 added
the D-36 binder that binds it. The unbound window between commits is invisible to the offline
suite (no offline test streams). Recorded as intended.

### Undocumented dependencies discovered and fixed (code wins)
1. **Session-init provider read (`:779` / SessionInitializer `data_provider`).** The plan never
   mentioned that `start()` reads `streaming[0].provider` for warmup/subscribe. Under D-36 the
   provider is on the binder, so both reads were repointed to `self._feed_binder.feed_provider`
   (a facade sentinel `_feed_binder` attached after construction — an assignment, not a new
   def/class/branch).
2. **`StreamRecoveryHandler` (Rule 1 auto-fix — real regression).** Its all-streams-health gate
   read the data provider off `lifecycle.provider`, now `None` under D-36 — silently dropping the
   candle-arm health check so resume could proceed while the data stream was down. Injected a
   live `feed_provider` callable (read through the binder, tracks a runtime re-borrow) and wired
   it in `build_live_system`. Caught only by `test_resume_stays_paused_while_data_arm_down`.
3. **`StreamRecoveryHandler` `venue_accounts` lambda / `venue_lifecycles` dict.** Re-sourced:
   `venue_accounts` is `{}` (no attach this plan); `venue_lifecycles` is rebuilt from each
   `bring_online` result keyed by account id.

### Blast radius exceeded the planned 10 files
Store-derived boot means an **offline** `build_live_system` assembles ZERO venue accounts
(vs. the old spec-derived default). This broke ~18 files, not 10:
- **Paper-replay harness (`tests/support/replay_harness.py`)** — the biggest root cause (~14
  tests: paper lifecycle, paper parity, multi-portfolio, reconfigure, strategy add/remove).
  Fixed by hand-wiring the replay provider to the feed (offline no longer auto-binds it).
- **OKX-boot tests** (okx-wiring, early-durable-halt, resume ×2, off-loop-halt) — converted to a
  shared `provisioned_okx` Postgres fixture + `tests/support/live_okx.py` helpers
  (`the_okx_lifecycle` / `the_feed_provider`) replacing `_primary_lifecycle` / `.provider`.
- **`test_off_loop_halt_write.py` moved `tests/unit/execution/` → `tests/integration/`** (it now
  needs a DB spine to assemble an okx exchange; folder-derived marker becomes `integration`).
- **`test_multi_account_composition.py` / `test_distinct_account_invariant.py`** rewritten:
  spec-derivation + spec-side-collision tests deleted as meaningless (D-37); multi-account is
  gated store-first; the venue-truth attach assertion (`is_venue_truth is True`) flipped to
  `False` (the transient compute-leaf window — see below).
- **`test_venue_uid_guard.py`** — the D-04 store/sink threading assertion moved from
  `build_live_system` source to `VenueAccountManager.bring_online` source (that is where it lives
  now).
- **`test_assemble.py`** — dropped the deleted `assemble_venues` / `primary_provider` tests.

### Manager surface expansion (Rule 3 cascade)
`VenueAccountManager.__init__` gained a required `feed_binder` collaborator (D-21 non-Optional
spirit preserved — it is a real dependency, not None-then-assign). Its two existing test
construction sites were updated with a no-op / recording binder.

### Deliberate transient window (owner-sanctioned, blocker 2)
No venue-truth account is attached to any portfolio this plan — every live portfolio sits on a
**compute leaf** (`is_venue_truth=False`) in a deliberate transient window. The
`PortfolioFactory → VenueAccountManager.account_for` wiring is **plan 08 (COMP-07)** and the
ACCT-03 raise is **plan 09**. No new venue-truth path was introduced here (that would collide
with plan 08).
