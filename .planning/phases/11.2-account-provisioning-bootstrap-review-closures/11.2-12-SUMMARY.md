# Phase 11.2 Plan 12: PortfolioHandler public read surface + per-entry degrade guards Summary

Added `PortfolioHandler.all_portfolios()` (a shallow copy of the registry, converging with the
existing `has_portfolio()`), converted the last production `_portfolios` reach-in
(`live_trading_system.py:1373`) to that public surface, and moved the degrade-clean guard inside
both `_layer_persisted_overrides` loops so one poisoned config no longer silences the rest.

## What shipped

- **`all_portfolios()`** on `PortfolioHandler` — returns `dict(self._portfolios)` (a shallow copy,
  never the live private dict), keyed by `portfolio_id`, every state, insertion order preserved,
  empty mapping (never `None`) on an empty registry. Cites ACCT-08 / D-41 / 11-REVIEW WR-09.
- **`has_portfolio()` was NOT re-added** — it already existed at `portfolio_handler.py:439` (plan
  09). Only `all_portfolios()` was added, so the `grep -c 'def all_portfolios\|def has_portfolio'`
  count goes `1 → 2` with no duplicate `def` (see Deviations).
- **Portfolio arm of `_layer_persisted_overrides`** — reads `portfolio_handler.all_portfolios()`
  instead of `._portfolios`, with the `try/except _degrade_clean` moved INSIDE the loop (per
  entry). `all_portfolios()` is a pure copy, so the loop needs no acquisition guard.
- **Venue arm** — the whole-loop defect (OQ3 / F-13) is fixed by splitting the guard: the
  `venue_store.read_all()` acquisition keeps its OWN guard (WR-03 schema-unavailable → boot
  degrades clean), and each per-row push is guarded per entry. No surviving whole-loop guard in
  either arm.

## Deviations from Plan (CODE WON OVER PLAN TEXT)

The plan predates waves 07/09/11, which already did most of what it described. The pre-dispatch audit
was correct; corrections recorded here.

**1. [Rule 1 — Plan/code drift] `has_portfolio` was NOT re-added (would have been a silent duplicate).**
- Task 1 text said "add `all_portfolios()` and `has_portfolio(...)`" with acceptance
  `grep -c '...' == 2`. But `has_portfolio` already existed at `:439` (plan 09; its docstring says
  "plan 12 should converge it rather than add a second predicate"). Re-adding `def has_portfolio`
  would create a duplicate method (Python silently keeps the last def), reverting plan 09's
  semantics with no test catching it.
- **Resolution:** added ONLY `all_portfolios()`. Pre-change `grep -c 'def all_portfolios\|def
  has_portfolio'` = 1; post-change = 2 (existing `has_portfolio` + new `all_portfolios`). Criterion
  satisfied correctly, no duplicate.

**2. [Rule 1 — Plan/code drift] Only ONE reach-in existed to convert; the other three were already gone.**
- `live_trading_system.py:1373` (`portfolio_handler._portfolios.items()`) was the sole production
  reach-in. `_attach_venue_accounts` (plan 07) was deleted; `portfolio_rehydrate.py:135` already
  uses public `has_portfolio()` (plan 09) — only doc/comment `_portfolios` mentions remain there.
- **`venue_account_manager.py` in `files_modified` was stale/speculative — NO CHANGE NEEDED.** It
  has zero `_portfolios`/registry reach-in (it only calls public `add_portfolio(...)`). No edit
  invented.

**3. [Rule 3 — Unsatisfiable acceptance criterion] Task 2's `grep -rc '_portfolios' itrader/`
"returns only portfolio_handler.py" is UNSATISFIABLE.**
- The substring `_portfolios` matches 24 files (`subscribed_portfolios`, `get_active_portfolios`,
  `max_portfolios`, the SQL `_portfolios` Table, rehydrate comments…).
- **Substituted** the discriminating check `rg -n 'handler\._portfolios' itrader/`: pre-change it
  returned the `:1373` reach-in site + one comment; post-change it returns ONLY the comment (now at
  `:1933`) — zero code sites. This is the check that actually targets the defect.

**4. [Rule 2 — Missing critical functionality] Venue arm needs a SEPARATE `read_all()` acquisition
guard the plan did not anticipate.**
- The plan modelled the venue fix as "one level of nesting" (move the whole-loop guard inside).
  But `VenueStore.read_all()` executes a SELECT and returns an eager list, so on an un-provisioned
  schema it raises `SQLAlchemyError` (a `_degrade_clean` member). Moving the guard FULLY inside the
  loop would let a `read_all()` failure crash boot — regressing the documented WR-03 contract
  (`_layer_persisted_overrides` docstring `:1291-1296`: "a boot against a not-yet-provisioned schema
  … must NOT crash").
- **Resolution:** split the guard — the `read_all()` acquisition keeps its own degrade guard
  (whole-scope, correct: no rows to iterate), and the per-row push is guarded per entry (OQ3/F-13).
  This is NOT the prohibited "surviving whole-loop guard": the acquisition guard wraps only the
  read, not the loop body. A new regression test
  (`test_venue_read_all_schema_unavailable_still_degrades_clean`) pins it.
- The portfolio arm needs no such guard — `all_portfolios()` is a pure in-memory copy that cannot
  raise `_degrade_clean`.

**5. [D-35 numstat — honest positive net, recorded per executor brief] `live_trading_system.py`
diff is +30 / −13 (insertions > deletions), so the plan's "insertions ≤ deletions" criterion is
NOT met.**
- The venue acquisition-guard split (Deviation 4) is genuinely additive code required for
  correctness, plus decision-anchored comments (WR-02/WR-03/OQ3/ACCT-08/D-41) that the codebase

## PortfolioReadModel Protocol decision (flagged assumption resolved)

`all_portfolios()` / `has_portfolio()` are placed on **`PortfolioHandler` only, NOT on the
`PortfolioReadModel` Protocol.** The Protocol (`core/portfolio_read_model.py`) is the narrow ORDER-
domain read boundary (`available_cash`, `get_position`, `reserve`, `release`, `total_equity`,
`open_position_count`). The full-registry / is-registered questions are consumed by the boot,
rehydrate, and FastAPI layers — not the order domain — so widening the Protocol would dilute its
documented purpose. This follows the precedent set by plan 09's `has_portfolio()`, which is also
handler-only.

## Flagged follow-up (NOT fixed here — out of scope)

**System arm of `_layer_persisted_overrides` (`live_trading_system.py:1319-1335`) has the IDENTICAL
whole-loop defect.** It wraps `for row in system_store.read_all(): setattr(...)` in ONE
`try/except _degrade_clean`, so one poisoned `config.system.*` / `config.universe.*` row skips every
system/universe field after it in iteration order with a single warning. The plan's OQ3/F-13 scope
is venue + portfolio ONLY (owner delegation), so the system arm was deliberately left untouched — but
it should be closed by the same acquisition-split + per-entry pattern in a future task. Not silently
expanded into this plan.
