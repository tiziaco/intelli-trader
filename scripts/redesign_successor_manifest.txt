# Successor manifest for the venue/account redesign must-have gate.
#
# Every file that replaces, absorbs or renames one of the 27 baseline files, plus every
# module the redesign introduces. Measured against the frozen EXTENDED baseline by:
#
#   poetry run python scripts/measure_redesign_baseline.py \
#       --manifest scripts/redesign_successor_manifest.txt --gate
#
# Kept in sync AS THE STAGES LANDED rather than authored at the end, so the sign of the
# must-have was observable throughout: a stage that trends it positive is a
# stop-and-report event, and that is only detectable if the manifest is current.
#
# WHAT THE COMPARAND IS. Not the 3,886 of the requirements' Scope block — that number
# counted 27 files, and several of the redesign's destinations were never among them, so
# lines were counted leaving and not counted arriving. The gate compares against
# measure_redesign_baseline.EXTENDED_BASELINE_TOTALS = 34 / 12,071 / 5,223: the same 27
# files PLUS every host that absorbed relocated code, all measured at the frozen
# pre-redesign commit 3a2c7692. This set must list those hosts or the script refuses to
# report a delta at all — an extended baseline against a successor set that omits them is
# the original asymmetry with its sign flipped.
#
# WHAT HAPPENED TO THE OLD SHAPE. Deleted, in stage order, with its successor named:
#
#   account/venue.py            -> AccountSnapshot, read by the execution adapter (stage 3)
#   venue_account_manager.py    -> venues/accounts.py, which also absorbed
#   assemble.py                    assemble / lifecycle / the TOFU guard (stage 4)
#   lifecycle.py
#   venue_uid_guard.py
#   feed_binder.py              -> build_okx_data_provider over the pool's own public
#                                  session, so there is no borrowed connection to bind
#                                  (stage 5)
#   live_trading_system.py      -> trading_system/live/{build,bootstrap,system}.py
#   compose.py                  -> trading_system/graph.py::build_handler_graph
#   venue_spec.py               -> build_live_system arguments; the selection is data
#   registry.py                 -> venues/catalog.py, plus the two venue constants re-homed
#                                  into execution_handler.py (counted below)
#   bundle.py / bundles.py      -> one root-owned (venue, account_id) -> adapter map
#   paper_plugin.py             -> execution_handler/exchanges/paper.py
#   okx_plugin.py               -> the recipes, beside the things they build
#   connectors/provider.py      -> connectors/pool.py                          (stage 7)
